# coopfix4g corpse1 尸体搜索错位尝试修复

基于官方v1.8.4固定提交54b3a858e228dc8807ed65bc3f9ac3c3f81b610d及匹配子模块，叠加已实测4g和netdiag1。新增四个客户端文件的修改，未改变网络编码、库存、箱子、尸体战利品、NPC家具恢复或掉落逻辑。BUILD_COMMIT仍为coopfix4g，现有4g服务器兼容；新增日志`STR corpse native motion`区分客户端修订，服务端保留netdiag1断线诊断（未修复断线根因）。

针对“尸体在A、客机须瞄准B才能搜索”：远端死亡NPC恢复原生位置更新，不再每帧把活人控制器位置、朝向和图变量写回尸体；迟到的生前动作不再覆盖死亡ActorState或重置尸体图。插值时钟、网络差分解码基线和来源位置仍保留。复活后恢复原有活人路径，远端玩家的自定义死亡流程保持原样。不是删除重建尸体，也不重置库存、不删除碰撞、不反复MoveTo。

目标是每端能在本端看到的尸体上出现搜索提示。仍未同步完整布娃娃骨骼：两端倒地姿态、滑落位置和搬运效果可能不同，远端尸体不再跟随活人位置插值；这是本次方案的实际限制。不能保证已经定位用户故障，也不能把编译通过当成游戏验证。VirtIsDead(false)和原生位置函数的效果仅有源码依据，没有IDA/Ghidra核实。原有生效的NPC起身和掉落修复均保留。

退出游戏后，两名玩家都备份并覆盖MO2中当前STR模组实际加载的SkyrimTogether.exe、EarlyLoad.dll。若同时更新服务器，停止服务器后覆盖其启动目录里的STServer.dll、SkyrimTogetherServer.exe；保持原STServer.ini、资源和依赖，tick true目标70/false60。不要只更新一名玩家，也不要覆盖SkyrimSE.exe。

先用新击杀的普通NPC测试：分别让两名玩家击杀，在尸体躯干、头和附近地面寻找“搜索”，双方打开同一尸体核对战利品及搜刮后消失；再测坡地滑落、离开区域返回、重连。顺便确认活人移动/攻击、朋友服装、已成功的家具起身、掉落拾取仍正常。可以另测存档中旧尸体，但不保证积累的旧物理状态能即时恢复。若失败，提供两端新tp_client.log、服务器日志及具体NPC/地点/是否新击杀，日志中的STR corpse native motion显示修复路径是否启用；断线需结合STR network detail/SDK记录另行定位。
