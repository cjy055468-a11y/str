# 布鲁玛城内第二客户端黑屏：STR 试修版 v1

适用：Skyrim SE 1.6.1170，现用 STR `master@v1.8.4-coopfix4g-corpse5-state1s-loot2-notice-board-v2-r1`。这是按“第二个客户端集中应用场景角色状态”方向制作的试修客户端，尚需两台电脑实测确认。

## 本次修改

- 接收网络包时只保存原始数据，结束接收循环后再按原顺序解码、应用。每次游戏更新最多处理一次角色分配、生成或接管；其余消息依次跟随，不能越过前面的初始状态。每批最多 512 个消息，并在处理完一条消息后检查 4 毫秒预算。
- 排队数据独立保存，避免引用已释放的网络包或解压临时内存。字符串缓存更新也保持顺序，不能提前解码后面的动画消息。
- 保留真实接收时间；远端动作回放时间受已应用消息的进度约束。断线时清空队列，重连不回放旧消息。
- 加入 `[STR scene-pacing v1]` 队列标记和 `[STR scene-diag v1]` 阶段日志，记录角色同步各步骤的开始、结束和耗时。

处理预算只能在两次调用之间让出游戏帧。如果单次游戏引擎调用本身不返回，分帧不能强制中断；这种情况仍需要用阶段日志继续定位。队列超过 8192 条或 32 MiB 会记录错误并断开连接，避免无限积压或静默丢弃状态。

本包不修改服务器、网络消息格式、NPC 数量、旅馆租金或 iNeed 设置；没有加入新的引擎钩子，也未使用此前的布鲁玛 ESM 来确定当前地图名称。原来的角色状态应用代码仅插入阶段日志。

## 安装

1. 两台电脑都退出游戏，分别备份实际 STR 程序目录中的 `SkyrimTogether.exe` 和 `EarlyLoad.dll`。
2. 将本包 `SkyrimTogetherReborn` 文件夹内的两个同名文件覆盖到实际 STR 程序目录。这是 STR 程序替换包，应直接覆盖程序目录，不要作为普通 ESP 模组启用。
3. 两台客户端都使用这版；服务器继续使用现有版本。此前的 iNeed 整合包及其他模组继续沿用，不需要重新设置 MCM。

## 测试

优先按你已确认的两种方式测试：

1. 第一人在布鲁玛城内露天街道，第二人从城内建筑出门到街道；交换先后出门的人再试。
2. 两人先断开服务器，都站在布鲁玛城内街道，然后先后连接服务器；交换连接顺序再试。

观察第二个人能否正常操作、双方能否看见对方与 NPC，随后再检查城内建筑和城外的普通同步。初始角色可能分批出现，完成后正常状态更新会继续。

如果仍黑屏，等约 5 秒供已有日志刷新线程写盘，复制两台电脑的 `logs/tp_client.log` 后再结束游戏，注明哪台黑屏及采用哪种复现方式。无需专门调查背包。

回退时退出游戏，还原备份的两个程序文件即可。编译、自动测试通过不等于已经证明布鲁玛问题解决，是否有效以这次双客户端实测为准。
