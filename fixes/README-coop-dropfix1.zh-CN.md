# STR 1.8.4 / Skyrim SE 1.6.1170 联机修复候选

此包基于官方 v1.8.4 提交 `54b3a858e228dc8807ed65bc3f9ac3c3f81b610d` 及该提交锁定的四个 Git 子模块。它包含玩家掉落物的服务器裁决流程，以及 NPC 动画空队列重置处理和诊断日志。实际编译结果、测试结果与三轮检查见随包 `logs/`；发布前必须全部通过。游戏内效果仍须双人实测。

## 安装

1. 退出游戏并关闭服务器，备份原文件和测试存档。
2. 两名玩家均使用原版完整 1.8.4 MOD 安装。在各自 `Data/SkyrimTogetherReborn/` 下覆盖 `SkyrimTogether.exe`、`EarlyLoad.dll`。MO2/Vortex 用户应覆盖管理器实际启用的 MOD 文件，避免修改未生效的副本。
3. 服务器使用包内同一版本的 `SkyrimTogetherServer.exe` 和 `STServer.dll`。若服务器就位于上述目录，在该目录覆盖；独立服务器则覆盖其实际启动目录。原配置和其他资源保留。
4. 在服务器实际读取的 `STServer.ini` 的 `[Gameplay]` 中设置 `bEnableItemDrops=true`，然后重启。官方默认值仍为 false；本修复保留默认配置行为。
5. 所有客户端和服务器必须配套。协议版本为 `master@v1.8.4-dropfix1`，会拒绝混用官方或旧候选版本。

本次一共交付四个二进制文件。客户端主逻辑链接在 EXE 中；它不是另一个 SKSE 修复 DLL。原 MOD 的 ESP、脚本、动画行为、Address Library、CEF 等依赖仍需保留，单独四个文件不能完整安装 MOD。

此前带有主动战斗目标修改的 `8d1e437` 候选已撤回。本包保留官方原有战斗目标、伤害及 AI 更新逻辑。

## 掉落物改动

原流程以背包数量变化通知他人生成本地物品，缺少地面实例的共享编号。`Actor::DropOrPickUpObject()` 中的 TODO 是相关线索，但只填这个分支无法识别到底拾取了哪一个同类物品。

新流程只接管连接期间玩家新丢出的物品：服务器分配实例 ID，客户端把本地引用绑定到该 ID。拾取先发请求，服务器只允许一次首次成功，随后广播消费状态，各端禁用并删除对应引用；获准者才增加背包物品。重复创建、重复领取和已消费实例分别有去重记录。NPC 拿取这些物品时也经过裁决，背包仍走原有同步处理。普通地图物品、箱子、尸体与其他容器保留原有流程。

服务器快照只重建仍然有效的掉落物。消费记录在同一次服务器运行期间保留，跨区域和重新连接均不应让它再次生成。同一游戏进程重连时保留已应用领取记录，处理未确认领取，避免重复授予。

当前范围和限制：

- 网络同步有延迟；这里的“立即消失”指收到服务器消费通知后禁用和删除，无法承诺零延迟。
- 服务器账本目前保存在内存中；不提供服务器重启后的存档持久化。完全退出游戏或崩溃后也不保证恢复尚未确认的领取。
- 远端一个视觉引用表示整个物品堆，准许领取时使用服务器记录的完整数量和额外数据；地面显示的数量或外观可能不完全一致。
- 运行期动态生成的基础物品无法用原协议的稳定 GameId 表示，创建请求会拒绝并返还物品。稳定基础物品及现有 Inventory::Entry 支持的额外数据走正常流程。
- 连接初始化或区域重同步尚未完成时，丢弃操作会暂缓；稍后重试。修复不扫描清理旧版本已遗留的重复物品。
- 断线恰好发生在丢弃注册或领取的中途，需重点核对背包总数；目前没有游戏引擎级端到端验证。

## NPC 改动与证据边界

服务器家具动画缓存可以产生 `ResetAnimationGraph=true` 且动作列表为空。原客户端把重置放在“有可播放动作”的分支内，漏处理这条指令。本包将它移到队列检查前，并保留原有重置方法；同时记录 NPC 所有权和重播状态，帮助确认剩余问题。

官方 PR 811 已讨论坐姿、站椅子、滑行等同步限制，尤其是连接前动作未被观察到的情形。本包没有重建未观测到的家具状态，不能声称所有坐姿、悬空、不追击都已解决。没有通过 IDA/Ghidra 验证引擎行为；现有拾取 hook、Papyrus 原生调用、线程与引用生命周期仍属基于源码的实现假设，已经用户同意尝试。

## 三轮检查

1. MSVC Windows x64 实际编译链接客户端、服务器；实际启动配套服务器生成配置；运行现有测试和新增的生产动画缓存、协议与并发账本测试。
2. 检查四个文件的 PE32+ AMD64 格式、客户端 1.6.1170 标记与修复标记、协议版本和 SHA-256。检查报告能证明构建内容，不能证明游戏引擎副作用。
3. 再次构建客户端及服务器，核对四个文件哈希保持一致；交付时核对构建提交、日志、测试报告及实际文件。

## 双人测试建议

使用备份后的测试存档。先确认两端都能进入同一配套服务器，再按以下顺序测，记录背包数量、地面引用与日志：

1. A 丢单个普通物品，B 看到后拾取；两端地面均消失，A 不能再拾取。再交换角色。
2. A 丢完整物品堆，分别测试 A 拾回、B 拾取，核对总数量守恒；同类物品丢两次，确认只消失被拾取的那一堆。
3. 同时按拾取键、连续快速按键，重复多轮，确认只有一个背包增加；测试 NPC 抢走武器的情形。
4. 拾取后两人离开再返回区域；保持服务器运行，分别断线重连，确认已消费实例不重现。还应专门在刚丢弃、刚拾取时断线，核对总数。
5. 测试普通装备、带现有附魔/名称等额外数据的物品；动态基础物品拒绝时确认没有损失。测试书籍阅读后拿取。
6. 验证原版箱子、尸体、商人、装备、任务与战斗流程仍正常。
7. 对 NPC 依次测试连接前已坐下、连接后坐下、战斗起身、两人交换进入区域顺序与控制权转移。两端记录同一 NPC 的表现，保留 `STR replay reset`、`STR replay audit v2`、`STR drop` 日志。
