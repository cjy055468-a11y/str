# corpse4l 源码审查：正向消息链

本轮按主机发起、服务器转发、客机执行的顺序追踪。基线是官方 v1.8.4 提交 `54b3a858e228dc8807ed65bc3f9ac3c3f81b610d` 加已测试的 corpse4g/corpse4k 改动。

1. **击杀来源**：`HookDamageActor` 在本地玩家击杀拥有的 NPC 时执行原生伤害路径；其它客户端接收血量广播。服务日志区分致命命中、负血量 relay、死亡状态请求及 owner/epoch 拒绝情况。
2. **死亡消息**：拥有该 NPC 的客户端轮询 `IsDead()` 变化并发请求。服务器核对当前 owner 和 epoch 后更新死亡状态并发通知。客机记录通知是否匹配实体、引用和 epoch；未加载的引用、待 3D 状态、`Kill()` 调用前后都各有日志。
3. **动画动作**：拥有者发出死亡相关 Ragdoll 动作；服务器记录请求来源、是否接受、转发给多少玩家。客机记录接收、引用未解析、动画图未就绪、延后和最终 `ForceAction` 结果，并记录执行前后的状态。
4. **客机本地物理更新**：对远端 NPC 死亡过渡，日志按状态变化记录客机 `IsDead`/虚拟死亡、生命位、Ragdoll、3D、根碰撞对象指针、进程标记和位置。`ActorProcess begin/end` 与 `suppressed` 是一次性记录，能看出 STR 是否放行了原生处理及状态是否发生变化。
5. **激活/搜索入口**：对准远端 NPC 并实际按交互键时，`TESObjectREFR::Activate` hook 记录目标引用和调用参数；STR `ActivateEvent` 记录其是否进入客户端服务；请求发送失败有原因；服务器记录收到与转发数量；接收客户端记录通知和 `Activate()` 返回值。

本轮确认现有源码没有准星/提示状态的 STR API。因而如果客机仍无提示且按键后没有 `Skyrim Activate hook`，日志把边界定位到 STR 交互回调之前，但不能凭这些日志断言是 Havok 碰撞、目标选择还是输入未触发。根节点 collision object 指针也不等于有效碰撞形状。这两项会在说明中保留为证据限制。
