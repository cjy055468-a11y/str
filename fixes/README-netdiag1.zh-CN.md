# coopfix4g 服务端断线诊断版 netdiag1

这是定位原因的诊断版，尚未修复或确认断线根因。客户端继续使用已实测的coopfix4g；只替换服务器的STServer.dll、SkyrimTogetherServer.exe。关闭服务器、备份两件原文件后覆盖同一启动目录，保留STServer.ini和所有资源，重启后看到`STR network diagnostics v1 enabled`表示本版已加载。bPremiumMode仍true目标70、false60，不改超时参数或游戏协议。

当前三份日志可以确认：服务器仍运行；客机若干已连接后的断开走代码2（对端关闭的通用标签），主机代码4前有disconnect指令；日志时间客机比服务器慢约一小时。反复重连后约11-12秒退出值得调查，但现有日志没有底层结束码，不能据此认定MOD、70tick或十秒时钟同步是原因。客机日志继续记录重连，相关事件没有呈现立即崩溃。

本版仅修改GameServer.cpp/.h诊断：SDK启用Msg级事件日志（无逐包内容），在连接被销毁前记录SDK状态、结束码、结束说明、寿命、已收包/字节数、最后解析的消息类型、距离最后收包时间、玩家绑定/角色分配状态；主动踢人分支明确记录是认证拒绝、缺失玩家绑定还是脚本拒绝。先记录再调用原关闭操作，原有判定和关闭行为不改。SDK诊断可能含IP等连接信息，上传日志时视为私有，不公开发布原始日志。

复现一次同样的双人连接/掉线即可，记下断开时间，保留完整STServerOut.log及客机tp_client.log。重点行前缀：`STR network detail`、`STR network app kick`、`STR network SDK`。不要只截取一条Disconnected提示。根据底层结束原因再决定修复分支，本版不宣称已解决随机断线。

完整补丁仍基于官方v1.8.4固定提交和匹配子模块；相对交付4g只有上述两个服务端文件改变，客户端、编码协议、尸体库存、NPC家具及掉落逻辑均不改。BUILD_COMMIT保持v1.8.4-coopfix4g是为了与原4g客户端通信，诊断修订由独立日志标记和文件哈希区分。日志与游戏测试结论分开；不得用编译通过代替实际断开原因。
