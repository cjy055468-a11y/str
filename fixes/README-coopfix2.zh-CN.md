# STR 1.8.4 / Skyrim SE 1.6.1170 — NPC 重复登记与尸体状态候选 coopfix2

基于官方 v1.8.4 提交 `54b3a858e228dc8807ed65bc3f9ac3c3f81b610d` 及其四个固定子模块，在已实际通过构建检查、且用户确认拾取后物品消失的 dropfix1 版本上继续修改。原掉落物服务、服务器裁决和相关拾取 hook 保留。

这是待双人游戏验证的候选。编译和数据测试不证明随机遭遇已完全修复，也不证明 NPC 仇恨、攻击与追击已解决。只有本次 Windows 构建和三轮检查全部通过才生成包；查看随包 logs。

## 修改与证据

用户日志中，农民临时引用 `FF00090C` 在卸载、重载后，依次被分配服务器实体 `100016`、`300004`、`500032`。另一个引用 `FF0008EC` 也出现相同类型记录。这是重复登记的具体证据；142 次“农民”生成调用包含重新加载，不能当成 142 个同时存在的角色。

- 新增客户端身份缓存，键为本地引用编号和引擎 handle 的代际值，保留卸载前的服务器实体身份；取消中的分配响应也保留绑定。断线时清空，避免接到另一个服务器后误用旧 ID。
- 分配请求增加可选 KnownServerId；服务器发现该临时 NPC 实体仍存在时返回已有实体及其当前控制权、死亡和背包快照，避免另建实体。服务器实体已销毁时允许正常登记。
- 已有远端代理和重新加载的原生引用同时对应同一服务器 NPC 时，客户端保留重载引用，退休同实体的旧临时代理；不会按名字或基础模板合并不同 NPC。
- 等待模型加载期间，匹配实体和 ownership epoch 的死亡通知、非 Drop 背包变化先合入待加载快照，防止稍后用旧生死/搜刮数据覆盖。原常规处理路径与服务器背包处理不变；过期 epoch 被拒绝，玩家不会经过延迟死亡处理。
- 保留 dropfix1 的空动画队列重置及诊断日志，保留原生战斗目标、伤害、AI 更新及移动钩子。

原生引擎的 handle 生命周期与删除调用副作用未通过 IDA/Ghidra 验证，属于用户已同意的源码接口实现假设。新日志 `STR NPC reattach request`、`STR NPC reattach`、`STR NPC duplicate proxy retired`、`STR corpse pending` 用于复测核对这些假设。

## 安装

退出双方游戏并关闭服务器，备份原文件及存档。包内 SkyrimTogetherReborn 目录有四个文件：

| 使用位置 | 覆盖文件 |
| --- | --- |
| 双方实际启用的 STR 目录（通常 Data/SkyrimTogetherReborn；MO2 使用实际启用 MOD 的目录） | SkyrimTogether.exe、EarlyLoad.dll |
| 实际服务器启动目录 | SkyrimTogetherServer.exe、STServer.dll |

若服务器也位于同一目录，就在该目录覆盖四个文件。保留原 MOD 其他资源和依赖，保留已有配置。日志、补丁、说明不需要复制到游戏目录。

本版改变分配请求格式，协议版本为 `v1.8.4-coopfix2`，服务器/runner 构建标记为 `master@v1.8.4-coopfix2`。双方和服务器必须配套，不能混用 dropfix1 或官方文件。开启掉落物同步仍需服务器 config/STServer.ini 的 [Gameplay] 下 bEnableItemDrops=true。

## 测试与边界

建议使用异常发生前的备份存档，重新启动服务器，双方使用本包再连接。已经生成的多个服务器实体或已写入存档的 NPC，不能安全地凭名字判断并删除，本包不批量清理已有农民。先保留问题存档和日志副本。

1. 重走出现农民的随机遭遇，反复离开/返回区域，交换先进入的玩家；观察是否持续增殖。新日志应显示同一有效引用恢复原实体，而非不断取得新实体。
2. 测试正常存在的多个同名 NPC、不同随机遭遇、召唤物、马、换区和断线重连，确认没有误合并或错误删除。
3. 杀死敌人后分别搜刮尸体，检查双方生死状态、物品数量；在死亡、搜刮的同时进入区域，离开再返回，确认没有复活、物品恢复或重复领取。
4. 复测上一版已成功的掉落物拾取，交换拾取者、同时拾取和重连，核对地面消失及总数量。
5. NPC 坐姿、起身、攻击、追击继续单独验证；本版不强制启动战斗或重写仇恨。

保留双方完整客户端日志及服务器日志。单进程客户端常用 tp_client.log，多开另有 instance 编号；MO2 实际路径受启动位置与重定向影响。用户本次日志确认其启动目录是实际 STR MOD 目录，不能笼统假定只在游戏 Data 目录查找。

身份恢复保证的范围是同一连接会话中、同一个仍有效的引擎引用 handle。不同客户端分别触发的独立随机遭遇不按姓名合并；新连接、已经销毁的原生引用不会凭一个复用的 FF 编号恢复旧角色。掉落物仍沿用上一版的内存账本及同进程重连范围，不新增存档持久化。

## 检查

Windows MSVC x64 实际编译客户端/服务器并启动服务器生成配置；运行所有原测试、dropfix1 测试和六个新的身份/协议/待加载快照测试。检查 PE 架构、1.6.1170 与修复版本标记和四文件 SHA-256，重复构建核对哈希。交付时再核对实际下载文件、提交、补丁和原导入/导出接口。游戏运行效果不计入这些自动检查。

源码变化完整清单见 coopfix2-v184.patch。相对 dropfix1 新改动集中在 CharacterService、WaitingForAssignmentComponent、ActorIdentityCache、分配请求编码、ActorValueService/InventoryService 的待加载前缀、PendingActorUpdates、构建版本和 actor_identity_pending.cpp；未改原掉落物实现。
