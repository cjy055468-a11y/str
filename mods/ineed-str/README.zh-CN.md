# iNeed × STR 兼容补丁 0.2 动画同步测试版

适用 Skyrim 1.6.1170、上传的 iNeed Continued 1.95，以及 STR `v1.8.4-coopfix4g-corpse5-state1s-loot2-notice-board-v2-r1`。更新同一个 `iNeed_STR_Compatibility.esp`，保留 0.1 的酒醉和睡眠修复。本版已经编译与结构核对，尚未完成双客户端游戏内验证。

## 安装

1. 所有玩家退出游戏，安装这一个压缩包，覆盖旧版 needstr 兼容补丁。
2. 保留原 iNeed；本补丁的脚本覆盖原 iNeed。启用 `iNeed_STR_Compatibility.esp`，排在 `iNeed.esp` 后。
3. 之前的 MCM 默认设置补丁继续保留。本包没有覆盖 `_SNQuestScript.pex`、`_SNSkyUIConfig.pex` 或 `iNeed.esp`，不会重置那三个默认设置。旅馆同步补丁也继续保留。
4. 所有客户端安装相同版本，服务器沿用当前程序。
5. A 的 iNeed 动画设置需要开启；站立测试选“启用/Enabled”。“仅坐姿”只发送坐姿动作，“关闭”不会产生吃喝动作。强制第三人称仍由 A 自己的 iNeed 设置控制。

## 动画同步

- A 在 iNeed 中真正开始吃喝时发送动作，B 在 A 的远程角色上重放。覆盖站立吃、站立喝、坐着吃、坐着喝；只覆盖 iNeed 原有吃喝动画。
- 沿用现有 STR 的法术效果同步通道：本机给自己施加不可见、无消耗、无伤害的短标记，STR 按玩家身份把标记转交给远程角色。标记收到后立即驱散，动画寿命单独管理。
- 远程脚本只接受 STR 标记的远程玩家，明确排除本机玩家。不会操作 B 的镜头、需求、物品或醉酒画面。
- 开始、停止带有会话和动作编号；旧动作结束通知不能结束较新的动作。读档与计数换轮使用新会话；较晚到达的同会话重置不会打断已经开始的动作。
- 保留 iNeed 原本本机事件顺序、7/7.5 秒等待、MCM 条件和镜头切换。坐姿事件遵循原本家具动画，避免用站立停止动作把远程角色拉离椅子。
- 标记只发给 STR 同步范围内的玩家，不补播范围外已经完成的吃喝。

## 原有修复

- 酒醉画面与踉跄只由喝酒者本机处理。原有画面参数、属性惩罚和饮酒逻辑保持不变。
- 睡眠继续使用原版 OnSleepStart/OnSleepStop，按游戏统计“累计睡眠小时”的实际增量恢复疲劳。选择 8 小时、实际完成 3 小时按 3 小时处理；保留 iNeed 的恢复公式，不改联机世界时间。
- 原有三个运行脚本按 SHA-256 原样保留，没有用本轮重新编译结果替换。

## 双人测试

1. A、B 进入同一场景并互相看见。A 站着吃一次，再喝水一次；B 应看到 A 对应动作，B 自己的镜头和角色不应被控制。
2. 互换 A/B 重测；再测试坐姿吃、坐姿喝。保持 iNeed 原本的本机等待时间后观察坐姿动作。
3. A 连续吃喝，以及两人同时吃喝；各自应看到对方动作，不串角色，旧动作结束不打断新动作。
4. A 在站立动作中移动、跳跃或拔武器，B 的 A 不应长期卡在吃喝姿势；再吃一次应能正常播放。
5. 读档后重新连接，再测试一次；传送到另一个场景后再吃喝。中途加入者从下一次动作开始观察。
6. 回测醉酒只影响喝酒者，以及实际睡 3 小时的疲劳恢复。

## 排查

启用 Papyrus 日志后搜索 `[iNeed-STR] consume`。动作编号：0 会话重置、1 站立吃、2 站立喝、3 坐姿吃、4 坐姿喝、5 停止。

- A 应出现 `send action=... token=...`。
- B 应出现 `receive actor=... action=... token=...`，角色应是 A 的远程角色。
- A 有 send、B 没有 receive：先核对双方补丁版本、ESP 是否启用、STR 同步范围和 STR 魔法同步日志。
- B 有 receive 但没有动作：记录站立/坐姿、动作编号、双方日志和所用动作/行为模组。这时需要在你的实际动画图上继续排查。

本环境没有 Skyrim 客户端；“编译通过、绑定核对通过”不能等同于“A/B 已实测同步成功”。若 STR 对远程角色的后续动画状态覆盖了重放动作，需要按游戏内结果继续修正。
