# STR corpse5：死亡后 1 秒的客机本地状态恢复实验

基准：用户指定 STR-coopfix4g-corpse4-test.zip，源码 f282f95cacaa33b179bc9da5d49496508f3367e2。
目标：尝试恢复“主机击杀后，客机看得见尸体但无法搜索”的问题。此为实验测试包，不宣称已实测修好。

## 具体行为

客机收到 NPC 已死亡的服务器状态后开始计时。满 1 秒，且3D/区域/处理器/动画图就绪时，对该远端 NPC 副本尝试一次；不要求先检测出卡死，也不依赖本地引擎已报告死亡：

1. 只将生命状态字段临时改为 8（Bleedout，濒死倒地），保留其余状态位。
2. 在同一次主线程处理中立即调用现有 Actor::Kill 原生死亡路径。
3. 如原生调用后仍未报告死亡，恢复此前生命状态字段并记录失败，不反复尝试。

不调用 Resurrect、Respawn、Reset、起身动画、动画图重置、额外 Ragdoll 动作或 MoveTo；不主动重设背包。服务器死亡状态保持不变，原来的远端死亡掉落拦截仍然有效。每个副本身份/所有权期的每次确认死亡最多尝试一次，不会每秒重复。新接收的既有尸体也可能接受这一次尝试。玩家、本地所有者、未确认死亡、未就绪及暂停状态不执行。

“不播放起身动画”是实现方式，不是游戏实测保证：原生死亡处理仍可能改变布娃娃姿态或产生短暂动作。此次重点验收是不站起来且恢复搜索；轻微布娃娃变化可接受。是否重复触发 Papyrus 死亡事件、任务脚本或第三方模组副作用，尚未通过游戏验证；不保证完全无副作用。

## 实验依据和限制

用户确认 E5F7B 强盗亡命徒起初不能搜索，后来在主机仍在线且同区域时恢复。日志 03:35:10.752：Ragdoll 动作 5DD59 返回 true，状态 01000041 的生命字段为 8；03:35:10.768 本地 dead/ragdoll 为 false，03:35:10.784 又为 true。该顺序提供实验依据，但日志没有“搜索成功”的直接标记，不能证明是哪一步产生恢复。

按用户“不让尸体站起来，只切状态再死亡”的要求，本实验只复现生命状态切换加原生 Kill，不额外重放那条 Ragdoll 动作。因此它不是对整个日志事件的逐项完整复制。仅有源码参考和用户授权，无 IDA/Ghidra 引擎核实，无 Skyrim 双人实测。

保留 corpse4 的尸体同步、loot1 装备计数、死亡语音、掉落及公告板 r1 修复；公告板 r2 和此前基于原始 coopfix4g 的新信件隔离实验均未加入。除新增计时策略、调用位置、配套测试和版本标识外，另只补全了激活失败日志的目标 ID，便于关联具体尸体。

## 安装

退出游戏，备份存档及 STR 程序。每位玩家覆盖实际启动 STR 目录里的 SkyrimTogether.exe、EarlyLoad.dll；开服者同时覆盖 STServer.dll、SkyrimTogetherServer.exe。四件均使用本包版本 coopfix4g-corpse5-state1s-loot1，不混用 corpse4 程序。
原配置、UI、资源和 Missives.esp/汉化保留；已安装 corpse4 自带公告板 r1 ESP/脚本者保持原样。包内 MissivesCompat 是原 r1 配套内容，不是此次新增功能。

## 测试

用备份后的测试存档，双方保持在线且同区域。先由主机击杀，客机全程不攻击：在死亡后 1 秒内和约 2 秒后分别观察搜索提示并尝试打开背包。交换击杀者测试。核对尸体没有站起来、物品数量和装备不重复、任务没有重复计数。另测试已搜索后取走物品、重新进区域、所有权交接和真实复活后的再次死亡。

客户端日志 STR corpse state refresh 1s 表示执行过尝试，不代表已能搜索；before/after、bleedout_dead、native_after_dead、ragdoll 和位置用于对照。激活错误现在附带 mod/base/local form/activator server ID。
如还不能搜索，请保留双方实际启动目录 logs/tp_client.log 和服务端日志，并报告哪具尸体、是否出现起身、刷新前后搜索是否变化。

## 构建验证

仅 Windows/MSVC 客户端与服务端编译、现有 103 项测试加 5 项纯计时/身份测试、18 个配套 PEX、服务端配置生成、源码清单及四程序 PE64/版本/哈希检查全部通过后打包。编译通过不等于游戏修复已确认。
